## Detailed Explanations

### 1. Drawing a Square: Mathematical & Coordinate Foundations

A square is a regular polygon characterized by four equal-length sides and four interior right angles ($90^\circ$). Rendering a 2D square on a digital canvas requires determining its dimensions, anchoring position, and mapping it to the underlying display grid.

#### Parameters Needed
* **Side Dimension ($s$)**: The extent of the square along horizontal and vertical axes ($\text{width} = \text{height} = s$).
* **Anchor Point**: Defined either by the shape's center $(\text{cx}, \text{cy})$ or its upper-left bounding corner $(x, y)$.

#### Screen Space vs. Cartesian Coordinates
Computer graphics pipelines typically employ an inverted Y-axis coordinate system:
* The origin point $(0, 0)$ is situated at the top-left vertex of the canvas or component.
* Values on the **X-axis** increase from left to right ($\longrightarrow$).
* Values on the **Y-axis** increase downwards ($\downarrow$), which is the opposite of the standard mathematical Cartesian plane.

```text
(0,0) ──────────────► +X
  │
  │
  │
  ▼
 +Y
```

#### Transforming Center Coordinates to Top-Left Bounding Box
Because graphics drawing routines in Java index shapes starting at their top-left corner, converting from a known center $(\text{cx}, \text{cy})$ requires offsetting by half the side length ($\frac{s}{2}$):

$$x = \text{cx} - \frac{s}{2}, \quad y = \text{cy} - \frac{s}{2}$$

If the square is centered inside a canvas of dimensions $W \times H$, the center is:
$$\text{cx} = \frac{W}{2}, \quad \text{cy} = \frac{H}{2}$$

#### Vertex Coordinates
The four vertices of a square can be evaluated through either representation:

| Vertex | Center-Based Calculation $(\text{cx}, \text{cy})$ | Anchor-Based Calculation $(x, y)$ |
| :--- | :--- | :--- |
| **Top-Left** | $\left(\text{cx} - \frac{s}{2}, \, \text{cy} - \frac{s}{2}\right)$ | $(x, \, y)$ |
| **Top-Right** | $\left(\text{cx} + \frac{s}{2}, \, \text{cy} - \frac{s}{2}\right)$ | $(x + s, \, y)$ |
| **Bottom-Left** | $\left(\text{cx} - \frac{s}{2}, \, \text{cy} + \frac{s}{2}\right)$ | $(x, \, y + s)$ |
| **Bottom-Right** | $\left(\text{cx} + \frac{s}{2}, \, \text{cy} + \frac{s}{2}\right)$ | $(x + s, \, y + s)$ |

#### Java2D Drawing Implementation
In Java2D, geometric outlines and solid fills are rendered using the top-left anchor $(x, y)$ along with width and height parameters:

```java
// Draws an unfilled square perimeter
g2d.drawRect(x, y, s, s);

// Draws a solid filled square
g2d.fillRect(x, y, s, s);
```

#### Dynamic Resizing & Component Centering
To keep a square automatically centered when a `JPanel` or window undergoes dynamic resizing, calculate its top-left coordinates relative to `getWidth()` and `getHeight()` within `paintComponent`:

```java
@Override
protected void paintComponent(Graphics g) {
    super.paintComponent(g);
    Graphics2D g2d = (Graphics2D) g.create();

    int side = 200;
    int x = (getWidth() - side) / 2;
    int y = (getHeight() - side) / 2;

    g2d.drawRect(x, y, side, side);
    g2d.dispose();
}
```

## 2. Anatomy of a Maven Project

Apache Maven enforces a standardized "convention over configuration" directory structure:

```text
my-graphics-app/
├── pom.xml                   # Project configuration and dependency descriptor
├── src/
│   ├── main/
│   │   ├── java/             # Production application source code (.java)
│   │   └── resources/        # Static assets, properties, configuration files
│   └── test/
│       ├── java/             # Unit and integration test suites
│       └── resources/        # Test-specific mock data and properties
└── target/                   # Generated bytecode, compiled .class files, JAR binaries
```

### Key Folders
* **`src/main/java`**: Houses package-structured Java source files (e.g., `package com.example;` maps to `src/main/java/com/example/`).
* **`src/main/resources`**: Contains assets accessible on the classpath at runtime (images, shaders, configuration files).
* **`src/test/java`**: Contains test runners and verification classes (e.g., JUnit).
* **`target/`**: Build destination populated by the compiler and packager. This directory is disposable and ignored in version control (`.gitignore`).

## 3. Configuration with `pom.xml`

The **Project Object Model (`pom.xml`)** file serves as the centralized manifest declaring metadata, build behaviors, and external library dependencies.

### Core Structure
* **Coordinates (GAV)**:
  * `groupId`: The organization or namespace (e.g., `com.example`).
  * `artifactId`: The unique identifier/name for the build artifact.
  * `version`: Current release/snapshot iteration (e.g., `1.0-SNAPSHOT`).
* **Properties**: Compiler source and target versions, character encoding (`UTF-8`).
* **Dependencies & Plugins**: External libraries (e.g., JUnit, logging) and execution plugins (e.g., `exec-maven-plugin`).

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>graphics-square</artifactId>
    <version>1.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.source>21</maven.compiler.source>
        <maven.compiler.target>21</maven.compiler.target>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>
</project>
```

### Essential Maven Lifecycle Commands

| Lifecycle Command | Description / Target Outcome |
| :--- | :--- |
| `mvn clean` | Deletes the `target/` directory and all prior build outputs. |
| `mvn compile` | Compiles `.java` files from `src/main/java` into `.class` files in `target/classes`. |
| `mvn test` | Executes test cases located under `src/test/java`. |
| `mvn package` | Compiles code, executes tests, and packages classes into a distributable archive (e.g., `.jar`). |
| `mvn clean compile exec:java` | Performs a clean compilation and executes the application main class. |

## 4. Java Desktop GUI & Rendering Stack

Java provides several layers and generations of graphical libraries:

```
┌──────────────────────────────────────────────────────────┐
│                         JavaFX                           │  Modern Scene Graph / CSS / FXML
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│                         Swing                            │  Lightweight GUI Components (JFrame, JPanel)
├──────────────────────────────────────────────────────────┤
│                        Java 2D                           │  Vector Drawing, Strokes, Gradients, Shapes
├──────────────────────────────────────────────────────────┤
│                         AWT                              │  Heavyweight OS Peers, Event Queue, Base Windowing
└──────────────────────────────────────────────────────────┘
```

### 1. Abstract Window Toolkit (AWT)
* Java's initial graphical toolkit introduced in JDK 1.0.
* Uses native operating system peers to render controls (**heavyweight components**).
* Provides core infrastructure: `Frame`, `Canvas`, `Color`, `Font`, event dispatching, and base `Graphics` context.

### 2. Swing
* Built upon AWT infrastructure as a pure Java, platform-independent GUI toolkit (**lightweight components**).
* Uses pluggable look-and-feel architecture; component class names typically start with `J` (e.g., `JFrame`, `JPanel`, `JButton`).
* **Thread Safety**: UI instantiation and mutations must run on the **Event Dispatch Thread (EDT)** using `SwingUtilities.invokeLater()` to avoid concurrency deadlocks or race conditions.

```java
import javax.swing.JFrame;
import javax.swing.SwingUtilities;

public class MainApp {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            JFrame window = new JFrame("Square Canvas");
            window.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            window.setSize(500, 500);
            window.setLocationRelativeTo(null);
            window.setVisible(true);
        });
    }
}
```

### 3. Java 2D API
* Advanced rendering subsystem built into AWT/Swing for 2D vector shapes, anti-aliased graphics, stroke styling, textures, clipping, and affine transformations.
* Custom drawing is implemented by overriding `paintComponent(Graphics g)` in a `JPanel`.
* Best practice involves casting to `Graphics2D`, creating a localized context via `g.create()`, and disposing of it via `dispose()` to isolate render states.

### 4. JavaFX
* A modern GUI toolkit built as an alternative to Swing.
* Employs a hardware-accelerated scene graph hierarchy.
* Supports CSS styling, visual effects, property bindings, and declarative XML interface definitions (FXML).
* Distributed as a standalone OpenJFX module in contemporary JDK distributions.

## Key Takeaways

* **Coordinate Orientation**: Digital canvas drawing uses an inverted Y-axis with $(0, 0)$ positioned at the upper-left corner.
* **Anchor Conversions**: Moving between a shape's center point and its top-left anchor point is achieved by adding or subtracting half the dimension width/height.
* **Dynamic Adaptation**: Centering formulas using `(getWidth() - size) / 2` and `(getHeight() - size) / 2` ensure rendering automatically responds to component resizes.
* **Maven Standardization**: Following standard Maven conventions guarantees predictable project organization, automated dependency management, and reproducible build pipelines across environments.
* **Graphics Architecture**: Swing provides lightweight UI widgets, Java2D drives custom shape and vector rendering, AWT handles base OS bridging and events, and JavaFX provides a modern scene graph framework.
