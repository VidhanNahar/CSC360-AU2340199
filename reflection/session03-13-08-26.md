## Detailed Explanations

### 1. Window Creation with `JFrame`
`JFrame` serves as the top-level window container in Swing desktop applications:
* **Initialization & Setup**:
  ```java
  JFrame frame = new JFrame("Square");
  frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
  frame.setSize(400, 400);
  frame.setLocationRelativeTo(null); // Centers window on screen
  ```
* **Content Management**: The custom drawing surface (`SwingSquare`) is attached via `frame.add(new SwingSquare())` before making the window visible (`frame.setVisible(true)`).

---

### 2. Custom Drawing Surface (`JPanel`)
`JPanel` acts as a lightweight, double-buffered container providing a dedicated canvas surface:
* **Overriding `paintComponent`**: Custom rendering logic must be placed inside `protected void paintComponent(Graphics g)`.
* **Clearing the Background**: Always invoke `super.paintComponent(g)` as the first statement to properly clear and repaint the component background.
  ```java
  @Override
  protected void paintComponent(Graphics g) {
      super.paintComponent(g);
      // Custom drawing routines...
  }
  ```

---

### 3. Java 2D Rendering Pipeline (`Graphics`)
The `Graphics` object represents the rendering context providing drawing tools and state:
* **Color Selection**: `g.setColor(Color.BLACK)` sets the active drawing color for subsequent render operations.
* **Shape Rendering**: `g.drawRect(x, y, width, height)` renders a hollow rectangular outline with a 1-pixel border.
  ```java
  g.setColor(Color.BLACK);
  g.drawRect(x, y, size, size);
  ```

---

### 4. Dynamic Coordinate Calculations
To ensure shapes remain centered regardless of window resizing or initial dimensions, coordinates are computed dynamically relative to component dimensions:
* **Formula for Centering**:
  $$x = \frac{\text{width} - \text{size}}{2}, \quad y = \frac{\text{height} - \text{size}}{2}$$
* **Code Implementation**:
  ```java
  int size = 200;
  int x = (getWidth() - size) / 2;
  int y = (getHeight() - size) / 2;
  ```

---

### 5. Thread Safety & Lifecycle
* **Painting Lifecycle**: The JVM invokes `paintComponent()` asynchronously when a component needs to be rendered, exposed, or resized. Painting code should never be placed in constructors or business logic.
* **Event Dispatch Thread (EDT)**: Swing GUI components should be initialized and modified on the EDT to prevent concurrency issues:
  ```java
  SwingUtilities.invokeLater(() -> {
      // Create and show GUI
  });
  ```

---

## Key Takeaways
* **Separation of Concerns**: `JFrame` manages the application window and OS interaction, while `JPanel` encapsulates custom rendering logic.
* **Rendering Rules**: Always invoke `super.paintComponent(g)` first to prevent visual artifacts and ghosting.
* **Dynamic Layouts**: Calculating rendering offsets from component dimensions (`getWidth()`, `getHeight()`) ensures responsive graphics that adapt to window resizing.
