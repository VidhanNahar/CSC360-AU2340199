## Detailed Explanations

### 1. Linear Systems & Geometric Modeling: Defining a 2D Triangle via Linear Algebra

In computational geometry and algebraic modeling, enclosing a closed triangular region in a 2D Cartesian space ($\mathbb{R}^2$) requires formulating systems of linear equations and half-space inequalities.

```text
              L1: a1*x + b1*y = c1
                   \         /
                    \   V1  /
                     \  /\ /
                      \/  \
                      /\   \
                     /  \   \
             V2 ----+----+---+---- V3  L2: a2*x + b2*y = c2
                   /      \ /
                  /        X
                 /        / \
                L3: a3*x + b3*y = c3
```

#### Algebraic Line Representation and System Formulation
A single infinite straight line within $\mathbb{R}^2$ is expressed in standard linear algebraic form:

$$a_i x + b_i y = c_i$$

To establish a closed triangular boundary using three intersecting lines ($L_1, L_2, L_3$), we construct a matrix-vector equation:

$$A\mathbf{x} = \mathbf{b} \quad \implies \quad \begin{bmatrix} a_1 & b_1 \\ a_2 & b_2 \\ a_3 & b_3 \end{bmatrix} \begin{bmatrix} x \\ y \end{bmatrix} = \begin{bmatrix} c_1 \\ c_2 \\ c_3 \end{bmatrix}$$

#### System Determinacy and Geometric Boundary Constraints
* **Underdetermined Configuration ($< 3$ Lines)**: 
  * A system of two non-parallel lines produces a single intersection point ($A \in \mathbb{R}^{2 \times 2}$).
  * Two lines partition the Cartesian plane into four infinite, open angular regions. Without a third boundary line to restrict the open space, an enclosed triangular region cannot exist.
* **Fully Determined Closed Region ($3$ Boundary Lines)**:
  * Three lines define a valid non-degenerate triangle if and only if:
    1. **Pairwise Non-Parallelism**: Slopes must differ across all pairs ($\frac{a_1}{b_1} \neq \frac{a_2}{b_2}$, $\frac{a_2}{b_2} \neq \frac{a_3}{b_3}$, $\frac{a_1}{b_1} \neq \frac{a_3}{b_3}$).
    2. **Non-Concurrency**: The lines must not converge at a single shared point. The augmented matrix $[A \mid \mathbf{b}]$ must maintain full rank ($3$), preventing trivial single-point intersection.

#### Vertex Extraction via Subsystem Intersection
The three corner vertices ($V_1, V_2, V_3$) are determined by solving three pairwise $2 \times 2$ linear sub-systems:

| Vertex | Intersecting Boundaries | Linear System Formulation | Coordinates |
| :--- | :--- | :--- | :--- |
| **$V_1$** | $L_1 \cap L_2$ | $\begin{cases} a_1 x + b_1 y = c_1 \\ a_2 x + b_2 y = c_2 \end{cases}$ | $(x_1, y_1)$ |
| **$V_2$** | $L_2 \cap L_3$ | $\begin{cases} a_2 x + b_2 y = c_2 \\ a_3 x + b_3 y = c_3 \end{cases}$ | $(x_2, y_2)$ |
| **$V_3$** | $L_3 \cap L_1$ | $\begin{cases} a_3 x + b_3 y = c_3 \\ a_1 x + b_1 y = c_1 \end{cases}$ | $(x_3, y_3)$ |

Connecting these vertices cyclically ($V_1 \to V_2 \to V_3 \to V_1$) establishes the perimeter. By converting equalities to half-space linear inequalities ($a_i x + b_i y \le c_i$ or $\ge c_i$), we delineate the convex hull representing the interior area of the triangle.

### 2. Abstract Data Types (ADTs): Stacks vs. Queues in State Management and Execution Flow

Stacks and Queues are fundamental linear abstract data structures that enforce strict behavioral constraints on how elements are inserted, accessed, and removed.

```text
  STACK (LIFO)                            QUEUE (FIFO)
  ┌──────────────┐                        ┌───────┬───────┬───────┐
  │ Item 3 (Top) │ ◄── Push / Pop         │ Item 1│ Item 2│ Item 3│
  ├──────────────┤                        └───────┴───────┴───────┘
  │ Item 2       │                           ▲               ▲
  ├──────────────┤                           │               │
  │ Item 1       │                        Dequeue         Enqueue
  └──────────────┘                        (Front)         (Rear)
```

| Operational Characteristic | Stack | Queue |
| :--- | :--- | :--- |
| **Discipline Policy** | **LIFO** (Last-In, First-Out) | **FIFO** (First-In, First-Out) |
| **Access Boundaries** | Single-ended (mutations restricted to the **Top**) | Double-ended (inserts at **Rear/Tail**, deletions at **Front/Head**) |
| **Core Methods** | `push(x)`, `pop()`, `peek()` | `enqueue(x)`, `dequeue()`, `peek()` |
| **Time Complexity** | $O(1)$ constant time for push/pop | $O(1)$ constant time for enqueue/dequeue |
| **Primary Use Cases** | Function call stacks, recursion, undo mechanisms, syntax parsing | Task scheduling, print buffers, breadth-first graph traversal |

#### State Tracking & The "Undo" (`Ctrl + Z`) Workflow Trace
Consider an interactive application tracking sequential editing operations:
1. **Op 1**: Insert string `"Hello"`
2. **Op 2**: Append string `" World"`
3. **Op 3**: Apply formatting `Bold`

```text
Queue Processing (FIFO) - Incorrect Semantics:
  [ "Hello", " World", "Bold" ] ──Dequeue──► Undoes "Hello" (Oldest operation erased first!)
  Result: Base text disappears while dependent " World" and "Bold" formatting remain corrupted.

Stack Processing (LIFO) - Correct Semantics:
  [ "Hello" ] ──► [ "Hello", " World" ] ──► [ "Hello", " World", "Bold" (Top) ]
  Triggering Ctrl+Z invokes pop():
  Pop() ──► Reverts "Bold" (Most recent action cleanly undone first)
```

* **Why Queues Fail for Reversals**: A queue processes elements in chronological arrival order. Invoking an undo via a queue eliminates the oldest foundational state, creating an inconsistent and broken document history.
* **Why Stacks are Required**: A stack preserves temporal recency. Pushing changes maintains an ordered snapshot history where the most recent mutation is positioned at the top, allowing clean rollback of dependent actions without affecting prior stable states.

### 3. Non-Linear Hierarchical Data Structures: Trees

Unlike sequential collections, trees structure information non-linearly using nested parent-child hierarchies, eliminating cyclical references.

```text
                  Root [A]              ── Depth 0, Level 0
                  /      \
               [B]        [C]           ── Depth 1, Level 1
              /   \          \
            [D]   [E]        [F]        ── Depth 2, Level 2
```

#### Core Terminology & Structural Properties
* **Node**: A data container holding payload values and child link references.
* **Root**: The topmost origin node with no incoming parent edge.
* **Edge**: A directed link connecting a parent node to a child. For any valid tree with $N$ nodes, there exist exactly $N - 1$ edges.
* **Leaf (Terminal Node)**: Any node with a degree of $0$ (possessing no children).
* **Depth vs. Height**:
  * **Depth**: Length of the path from the root down to a given node ($Depth(Root) = 0$).
  * **Height**: Length of the longest descending path from a node down to a leaf node.

#### Common Tree Classifications
1. **General Tree**: Nodes may contain an arbitrary, unbounded number of child nodes.
2. **Binary Tree**: Each node contains at most two children, traditionally designated as `left` and `right`.
3. **Binary Search Tree (BST)**: Imposes an ordering invariant where for any node $X$, all keys in the left subtree are strictly smaller ($\text{Left} < X$) and all keys in the right subtree are strictly greater ($\text{Right} > X$).

#### Tree Traversal Paradigms
Tree traversal systematically visits every node in the hierarchy exactly once:

```text
           [1]
          /   \
        [2]   [3]
        / \
      [4] [5]
```

1. **Depth-First Search (DFS)**:
   * **Pre-Order ($Root \to Left \to Right$)**: `1 → 2 → 4 → 5 → 3`  
     *Useful for serialization, cloning structure, and prefix expression parsing.*
   * **In-Order ($Left \to Root \to Right$)**: `4 → 2 → 5 → 1 → 3`  
     *Yields keys in strictly sorted ascending order when executed on a Binary Search Tree.*
   * **Post-Order ($Left \to Right \to Root$)**: `4 → 5 → 2 → 3 → 1`  
     *Optimal for bottom-up cleanup, node deletion, and postfix/RPN evaluation.*
2. **Breadth-First Search (BFS) / Level-Order**:
   * Explores nodes layer-by-layer horizontally: `1 → 2 → 3 → 4 → 5`.
   * Implemented iteratively using a FIFO Queue to track discovered children.

## Key Takeaways

* **Geometric Triangle Enclosure**: A 2D triangle requires three pairwise non-parallel and non-concurrent linear equations; the interior region is bounded by the intersection of three half-space linear inequalities.
* **Stack Temporal Semantics**: LIFO structures ensure that state rollbacks (undo/redo, call frames, expression evaluation) revert the most recent operations first, maintaining causal consistency.
* **Queue Scheduling Semantics**: FIFO structures prioritize fairness and arrival sequence, making them suitable for message streaming, asynchronous task queues, and level-order traversals.
* **Hierarchical Tree Organization**: Trees model recursive relationships with $N-1$ edges, supporting fast logarithmic operations in balanced structures.
* **Traversal Specialization**: DFS strategies (Pre/In/Post-order) leverage recursive stack semantics for hierarchical parsing and sorted retrieval, whereas BFS uses queue-driven level traversal for layer-wise inspection.
