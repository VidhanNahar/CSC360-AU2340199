#### Custom JavaFX ComboBox Cell Factory

Standard JavaFX `ComboBox` controls styled with CSS often suffer from unstyled popup list cells, inconsistent hover states, or mismatched selection text contrast. To enforce dark-theme visual coherence, custom `ListCell` factories were applied to both the button cell (visible selection) and popup dropdown rows:

```java
import javafx.scene.control.ComboBox;
import javafx.scene.control.ListCell;

public final class PresetUiConfig {

    public record MatrixPreset(String name, double[][] matrix) {}

    public static void configurePresetComboBox(ComboBox<MatrixPreset> comboBox) {
        // Factory for dropdown popup items
        comboBox.setCellFactory(listView -> new ListCell<>() {
            @Override
            protected void updateItem(MatrixPreset item, boolean empty) {
                super.updateItem(item, empty);
                if (empty || item == null) {
                    setText(null);
                    setGraphic(null);
                    setStyle("-fx-background-color: transparent;");
                } else {
                    setText(item.name());
                    setStyle("-fx-text-fill: #E2E8F0; -fx-padding: 8px 12px; -fx-background-color: #1E293B;");
                    
                    setOnMouseEntered(e -> 
                        setStyle("-fx-text-fill: #38BDF8; -fx-padding: 8px 12px; -fx-background-color: #334155; -fx-cursor: hand;"));
                    setOnMouseExited(e -> 
                        setStyle("-fx-text-fill: #E2E8F0; -fx-padding: 8px 12px; -fx-background-color: #1E293B;"));
                }
            }
        });

        // Cell for the currently selected display button
        comboBox.setButtonCell(new ListCell<>() {
            @Override
            protected void updateItem(MatrixPreset item, boolean empty) {
                super.updateItem(item, empty);
                if (empty || item == null) {
                    setText("Select a Geometric Preset...");
                    setStyle("-fx-text-fill: #94A3B8;");
                } else {
                    setText(item.name());
                    setStyle("-fx-text-fill: #F8FAFC; -fx-font-weight: bold;");
                }
            }
        });
    }
}
```

### 4. Decoupled Computational Geometry and Metric Evaluation

The core geometry engine solves an overdetermined matrix system representing three lines in standard 2D space:

$$A \cdot \mathbf{x} = \mathbf{B}$$

where:

$$A = \begin{bmatrix} a_1 & b_1 \\ a_2 & b_2 \\ a_3 & b_3 \end{bmatrix}, \quad \mathbf{x} = \begin{bmatrix} x \\ y \end{bmatrix}, \quad \mathbf{B} = \begin{bmatrix} c_1 \\ c_2 \\ c_3 \end{bmatrix}$$

Each row defines one linear equation $L_i: a_i x + b_i y = c_i$.

```text
                           L₁: a₁x + b₁y = c₁
                                /  \
                               /    \
                             P₁₂    P₃₁
                             /        \
              ──────────────X──────────X───────────── L₃: a₃x + b₃y = c₃
                           /            \
                          /              \
                        L₂                P₂₃
                   a₂x + b₂y = c₂
```

#### Determinant-Based Intersection (Cramer's Rule)

For each pair of lines $(L_i, L_j)$, the $2 \times 2$ coefficient determinant $D$ is computed:

$$D = \begin{vmatrix} a_i & b_i \\ a_j & b_j \end{vmatrix} = a_i b_j - a_j b_i$$

* If $|D| < \epsilon$ ($\epsilon = 10^{-9}$), the two lines are **parallel** (or **coincident** if their constant proportions match), meaning they do not form a unique intersection vertex.
* If $|D| \ge \epsilon$, a unique Cartesian intersection coordinate $P(x, y)$ is obtained via determinants:

$$D_x = \begin{vmatrix} c_i & b_i \\ c_j & b_j \end{vmatrix} = c_i b_j - c_j b_i, \quad D_y = \begin{vmatrix} a_i & c_i \\ a_j & c_j \end{vmatrix} = a_i c_j - a_j c_i$$

$$x = \frac{D_x}{D}, \quad y = \frac{D_y}{D}$$

#### Metric Property Calculations

Once three valid intersection points $P_{12}, P_{23}, P_{31}$ are established, secondary geometric metrics are derived:

1. **Euclidean Edge Lengths**:
   $$d(P_a, P_b) = \sqrt{(x_b - x_a)^2 + (y_b - y_a)^2}$$
2. **Triangle Perimeter**:
   $$\mathcal{P} = d(P_{12}, P_{23}) + d(P_{23}, P_{31}) + d(P_{31}, P_{12})$$
3. **Enclosed Shoelace Area**:
   $$\text{Area} = \frac{1}{2} \left| x_1(y_2 - y_3) + x_2(y_3 - y_1) + x_3(y_1 - y_2) \right|$$

If the computed area is $\le \epsilon$, the three intersection points are collinear or concurrent, and the shape is rejected before reaching the canvas.

### 5. Cartesian Canvas Rendering and Headless Testing Strategies

Drawing geometric figures accurately on a digital display requires resolving the spatial discrepancy between standard Cartesian mathematics and pixel-based display hardware.

```text
       CARTESIAN MATHEMATICAL SPACE               JAVAFX CANVAS PIXEL SPACE
                 +y (Upward)                      (0,0) ──────────────────► +x'
                  │                                 │
                  │   • P(x, y)                     │       • P'(x', y')
                  │                                 │
       ───────────┼───────────► +x                  │
                  │                                 ▼
                  │                                +y' (Downward)
```

#### Dynamic Viewport Auto-Scaling

To ensure that triangles of any scale fit comfortably inside the canvas viewport, the rendering engine computes an Axis-Aligned Bounding Box (AABB) around the vertices:

$$x_{\min} = \min(x_1, x_2, x_3), \quad x_{\max} = \max(x_1, x_2, x_3)$$
$$y_{\min} = \min(y_1, y_2, y_3), \quad y_{\max} = \max(y_1, y_2, y_3)$$

With canvas dimensions $W \times H$ and padding $M$, the uniform scaling factor $S$ and pixel mappings are:

$$S = \min\left(\frac{W - 2M}{\max(x_{\max} - x_{\min}, \delta)}, \frac{H - 2M}{\max(y_{\max} - y_{\min}, \delta)}\right)$$

$$x' = M + (x - x_{\min}) \cdot S$$
$$y' = H - \left(M + (y - y_{\min}) \cdot S\right)$$

The vertical inversion ($H - \dots$) restores the intuitive mathematical orientation, placing positive $y$ values higher on the screen.

#### Automated JUnit Testing Matrix

By keeping the geometry engine completely independent of JavaFX UI components, automated JUnit tests run in headless environments:

| Test Case | Inputs Tested | Expected Assertion |
| :--- | :--- | :--- |
| **Unique Intersection** | $x + y = 4$ and $x - y = 0$ | Yields point $(2.0, 2.0)$ with $|D| > \epsilon$. |
| **Parallel Lines** | $2x + 4y = 8$ and $x + 2y = 10$ | Determinant evaluates to $0.0$; flags non-intersecting pair. |
| **Coincident Lines** | $x + y = 3$ and $2x + 2y = 6$ | Infinite intersections flagged; degenerate triangle. |
| **Concurrent Lines** | Three lines passing through $(1, 1)$ | Duplicate vertices detected; area evaluates to $0.0$. |
| **Collinear Vertices** | Points lying on line $y = 2x$ | Shoelace area is $0.0$; rejected as non-triangle. |
| **Floating Precision** | Equations with repeating decimals | Precision threshold $\epsilon = 10^{-9}$ preserves stability. |

## Discussion

1. **Curating UI Simplicity by Pruning Redundant Features**:
   * Software development often suffers from feature creep, where new input modes are added without considering their cognitive impact on users. In TriangleFX, removing the raw multiline matrix paste panel was a conscious decision to favor a single, polished input pipeline (the structured 3×3 grid plus curated presets). This eliminated duplicate validation logic, reduced the maintenance surface of `TriangleApp`, and made demonstrations significantly smoother.
2. **Defensive Control Customization in JavaFX**:
   * Styling complex controls like `ComboBox` purely with inline CSS strings or external stylesheets frequently yields inconsistent results across operating systems. The visual container, the selected button cell, and the popup list view rows require individual handling. Utilizing programmatic cell factories with dedicated event listeners (`setOnMouseEntered`, `setOnMouseExited`) guarantees full theme consistency and immediate interactive feedback.
3. **Living Documentation as an Engineering Deliverable**:
   * A software project is only as accessible as its documentation. By integrating verified Maven lifecycle commands, architecture diagrams, mathematical formulations, and visual application captures into `README.md`, the repository allows collaborators and evaluators to understand, test, and run the system without having to inspect internal source files first.

## Key Takeaways

* **Separation of Architectural Concerns**: Strict layering between JavaFX UI controllers, matrix input parsers, and computational geometry services ensures that mathematical models can be tested headlessly with JUnit.
* **Collaborative Git Practices**: Leveraging branch-and-PR workflows (demonstrated in PR #2) and atomic documentation commits (`779c8aa`) keeps the `main` branch stable, auditable, and production-ready.
* **Intentional UI Minimalism**: Removing redundant interface components—such as the raw paste text area—strengthens the primary user workflow and reduces error-prone code branches.
* **Rigorous Degeneracy Screening**: Validating a triangle requires checking for parallel lines ($D = 0$), coincident equations, concurrent intersections, and non-zero Shoelace area using numerical epsilon tolerances.
* **Cartesian-to-Canvas Mapping**: Restoring natural Cartesian orientation on a JavaFX canvas requires inverting the vertical coordinate axis ($y' = H - y_{\text{scaled}}$) and applying dynamic bounding-box scaling.
